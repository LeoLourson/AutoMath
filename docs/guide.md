# Руководство пользователя

Шаблон создаёт папку исследовательского проекта по одной математической теме. В проекте
работает DeepSeek Harness или Claude Code: вы открываете папку проекта, пишете команды
вида `/ideas` или `/formalize R07`, а среда запускает нужных агентов и возвращает отчёт.

Проект ведёт утверждение от замысла до статьи:

1. источник найден, скачан, и его теорема сверена с PDF;
2. идея предложена и пережила критику;
3. доказательство записано и прошло рецензию;
4. утверждение доказано в Lean 4, и отдельная проверка подтвердила, что теорема Lean означает то же, что написано на бумаге;
5. результат внесён в статью.

Постановка задачи, новые определения, изменение условий и коммиты
в Git остаются вашими решениями; агенты выносят их в конец отчёта и ждут.

## Что установить

- Python 3.11 или новее;
- `uv` — запускает скрипты проекта и сам ставит их зависимости;
- `elan` вместе с `lake` — Lean 4;
- `git`;
- DeepSeek Harness (Node.js 22.19+ в ветке 22 или 24+, npm) или Claude Code;
- `pdflatex` — нужен для статьи и для проверки транскрипций, без него остальное работает.

## Шаг 1. Создать проект

Из папки шаблона:

```
python tools/create.py ..\Spectra --lib Spectra --title "Название темы"
cd ..\Spectra
lake exe cache get
lake build
python scripts/state/proj.py doctor
python scripts/state/proj.py check
```

`--lib` — имя библиотеки Lean и пространства имён: латиница, с заглавной буквы, без
пробелов. `lake exe cache get` скачивает готовую сборку Mathlib, иначе `lake build`
займёт часы. `doctor` проверяет окружение, `check` — сам проект; в свежем проекте `check`
выдаёт одно замечание о записи-примере.

Один раз выполните `uv run scripts/sources/lit.py list`: команда поставит зависимости поиска по
литературе, и редактору не придётся ждать этого при первом запуске.

Для DeepSeek Harness запустите `python scripts/host/harness.py run web`, выберите папку
проекта и preset Standard, настройте модель и ключ в интерфейсе Harness. Создание
проекта уже подготовило skills, роли и MCP; запуск обновит их при необходимости.
Полная инструкция — [DEEPSEEK.md](../template/DEEPSEEK.md), она также лежит в созданном проекте.

## Шаг 2. Записать постановку

Заполните два файла. От них зависит вся дальнейшая работа: агенты читают их в начале
каждой задачи.

`question.md` — точная постановка:

- объект и условия, каждое условие формулой;
- вопрос, без указания метода;
- контрольные случаи — частные случаи с известным ответом; по ним критик проверяет идеи,
  а экспериментатор — методы расчёта;
- открытые вопросы с номерами `Q1`, `Q2`, …

`PROJECT.md` — тема в одном абзаце, обозначения, особые правила. Раздел «Ловушки» в нём
сначала пуст: его пополняют агенты критик и рецензент, когда находят вывод, который в этой теме выглядит интуитивно верным, но неверен.

После этого удалите примеры: файл `results/R01.md` и теорему `sq_add` из `Basic.lean` в
папке библиотеки, затем выполните `python scripts/state/proj.py sync`.

## Шаг 3. Работать командами

Команды набираются в Harness (выбор skill в меню `/`) или Claude Code, открытом в папке проекта. Ниже они стоят в том порядке,
в каком обычно нужны в новой теме.

| Когда | Команда | Что получаете |
| --- | --- | --- |
| нужна литература | `/sources тема` | источники в реестре, полные тексты, карточки теорем |
| источник пришёл как PDF | `/transcribe S12` | LaTeX источника с номерами страниц и теорем |
| нужен подход к вопросу | `/ideas Q1` | идеи с вердиктом критика |
| доказательство записано | `/referee R07` | построчная рецензия |
| доказательство принято | `/formalize R07` | теорема в Lean и проверка соответствия |
| формулировки менялись | `/fidelity` | повторная проверка соответствия |
| появился значимый результат | `/exposition` | обновлённая статья |
| каждый рабочий день | `/day` | весь цикл сразу и отчёт |

### Литература: `/sources`

`/sources спектр несамосопряжённого оператора Штурма — Лиувилля` сначала ищет ответ в уже
скачанных текстах, затем подбирает кандидатов в zbMATH, arXiv и журналах MathNet, отбирает
их по аннотациям и скачивает. Каждый источник получает код `S1`, `S2`, … С arXiv приходит
авторский LaTeX, с MathNet — PDF, по одному DOI — только описание.

Статью, которой нет в открытом доступе, вы добавляете сами:
`python scripts/sources/lit.py attach S31 путь\к\файлу.pdf`.

Теорему источника нельзя использовать как посылку, пока у неё нет карточки в
`sources/cards/`. Карточка содержит номер теоремы, страницу, все гипотезы вместе с
соглашениями раздела и вывод. Её сверяет с PDF отдельный агент, после чего в шапке
появляется отметка `verified`. Кусок текста, найденный поиском, карточку не заменяет:
условия теоремы часто стоят страницей выше.

### PDF в LaTeX: `/transcribe`

Нужна для статей с MathNet и для прикреплённых PDF, по которым будут строиться
доказательства. Агенты читают страницы по порядку и пишут LaTeX с печатными номерами
страниц и утверждений, поэтому поиск потом показывает «Теорема 6.6, с. 41».

Транскрипцию делает модель. Место, прочитанное неуверенно, помечено `\unsure{…}`; такую
метку снимаете только вы, сверив с оригиналом. При расхождении прав PDF.

### Идеи: `/ideas`

`/ideas Q2` запускает генератор идей, затем критика по каждой идее. Критик видит только
файл идеи и пытается её опровергнуть: проверяет на контрольных случаях, ищет пробел,
сверяется с отвергнутыми идеями. Итог записан в файле `ideas/I*.md` и в сводке
`ideas/README.md`:

- `выдержала критику` — можно писать доказательство;
- `новая` с пометкой о пробеле — в файле сказано, чего не хватает;
- `отвергнута` — файл остаётся с причиной, чтобы ту же идею не предложили снова.

Если судьба идеи зависит от расчёта, критик описывает опыт, и его ставит экспериментатор.
Опыт лежит в `experiments/E*/` и запускается одной командой из своего `README.md`. Опыт
согласуется с гипотезой или опровергает её; доказательством он не считается.

### Доказательство и рецензия: `/referee`

Доказательство пишется в запись `results/R*.md` — на утверждение свой файл с разделами
«Утверждение», «Доказательство», «Границы». Запись создаёт команда
`python scripts/state/proj.py new result "Название"`; текст можете написать вы или попросить об
этом Claude обычным сообщением.

`/referee R07` отдаёт запись рецензенту. Вердикты:

- `принято` — мелкие неточности исправляются в тексте;
- `пробел` — запись возвращается в статус «набросок», недостающие леммы становятся
  отдельными целями;
- `ошибка` — если неверно само утверждение, запись получает статус «опровергнуто» и
  остаётся в проекте с причиной.

После исправления рецензия проводится заново: прежний вердикт на новый текст не
переносится.

### Lean: `/formalize` и `/fidelity`

`/formalize R07` запускает формализатора. Он пишет формулировку и доказательство в
библиотеке Lean и останавливается в трёх случаях, о каждом из которых вы узнаёте из
отчёта:

- формулировка в Lean расходится с записью — решаете вы;
- не доказывается лемма — заготовка лежит в `output/drafts/`;
- доказано более слабое утверждение — оно получает своё имя и свою запись, а исходная
  цель остаётся целью.

Когда теорема собралась, второй агент отвечает на отдельный вопрос: означает ли теорема
Lean то же, что утверждение записи. Он не видит отчёта формализатора. Вердикт
«соответствует», «соответствует с оговорками» или «не соответствует» вносится в шапку
записи вместе с отпечатком формулировки. Если позже формулировка или определения, на
которые она опирается, изменятся, отпечаток перестанет совпадать, и `proj.py check`
сообщит, что проверка устарела. Тогда запускается `/fidelity`.

В библиотеке запрещены `sorry`, `axiom`, `native_decide` и отключение линтеров; `check`
их ищет и выписывает аксиомы, от которых зависит каждая теорема. Допустимый список —
`propext`, `Classical.choice`, `Quot.sound` — задан в `project.toml`.

### Статья: `/exposition`

`/exposition` без аргумента читает `paper/main.tex`, сравнивает его с записями и вносит то,
после чего аннотация или анонс статьи должны измениться: новый класс данных, усиление
вывода, ослабление гипотезы, закрытый вопрос, пример или контрпример. Лемма входит как
ступень доказательства вносимого результата. Вносится только запись с принятой рецензией
либо с доказательством в Lean и проверенным соответствием; результаты, которые уже стоят в
статье без такой проверки, команда не трогает и перечисляет в отчёте. Lean, агенты и номера
записей в тексте статьи не упоминаются.

С аргументом команда делает то, что названо: `/exposition внеси R07` — полный проход,
`/exposition поправь ссылку в лемме 3` — правка по месту и сборка.

Текст ведут пять скиллов проекта, по одному на слой: `math-rigor` отвечает за содержание
(верно ли утверждение и можно ли его проверить), `paper-canvas` — за композицию (что
сказано и что главное), `shkalikov-style` — за стиль автора, `paper-de-ai` — за язык (слова
без содержания), `math-typeset` — за набор формул и окружений. Другой стиль указывается в
`PROJECT.md`.

### Ежедневный цикл: `/day`

`/day` проходит всё перечисленное без вопросов к вам: проверяет состояние проекта,
предлагает идеи по одной-трём целям, выбирает одну цель дня и работает над ней. Цель
выбирается в таком порядке: формализовать запись с принятой рецензией; отрецензировать
доказанное; написать доказательство по идее, выдержавшей критику; разобрать замечания
проверки. Пожелание можно дать аргументом: `/day займись Q2, без Lean`.

В конце — отчёт: что доказано и формализовано, вердикты проверок, судьба идей, что
осталось открытым, решения за вами и предложенное сообщение коммита.

## Где лежит информация о текущем состоянии проекта

| Файл | Что в нём |
| --- | --- |
| `blueprint.md` | все записи, их статусы и граф зависимостей |
| `ideas/README.md` | все идеи с вердиктами критика |
| `sources/catalog.md` | источники со ссылками и статусами |
| `question.md`, раздел «Ответ на …» | короткий ответ на вопрос со ссылками на записи |

Первые три файла собирает `python scripts/state/proj.py sync` из шапок записей; руками они не
правятся.

Шапка записи показывает, насколько утверждению можно верить:

| Поле | Значение |
| --- | --- |
| `status` | `цель`, `набросок`, `доказано` или `опровергнуто` — состояние бумажного доказательства |
| `review` | дата и вердикт рецензента |
| `lean` | имена теорем Lean, доказывающих утверждение |
| `fidelity` | дата и вердикт проверки соответствия |
| `depends`, `sources` | записи и источники, на которые опирается доказательство |

«Доказано» без `review` значит, что доказательство написано, но его никто не проверял.
Заполненное `lean` без `fidelity` значит, что Lean что-то доказал, но совпадение с
бумажным утверждением не подтверждено.

Буквы в номерах: `R` — запись результата, `I` — идея, `S` — источник, `E` — опыт, `Q` —
открытый вопрос. Номера не переиспользуются.

## Что остаётся за вами

- постановка в `question.md` и любое изменение условий;
- новое определение, от которого зависит смысл итоговой теоремы: формализатор
  останавливается и спрашивает;
- версии Lean и Mathlib: агенты их не меняют;
- файлы закрытых статей — команда `attach`;
- метки `\unsure` в транскрипциях;
- коммиты: агенты предлагают сообщение, коммит делаете вы;
- отправка задач в сервис Aristotle: только по вашей прямой просьбе, ключ передаётся
  переменной окружения `ARISTOTLE_API_KEY`.

## Инструменты без Claude

Всё, что делают команды, доступно и из терминала.

Проект — `python scripts/state/proj.py …`:

| Команда | Действие |
| --- | --- |
| `check` | все проверки, включая сборку Lean и аксиомы; `check --fast` — без Lean |
| `sync` | пересобрать сводки |
| `new result "Название"` | новая запись; так же `new idea`, `new card S4`, `new experiment` |
| `set R05 status доказано` | изменить поле шапки |
| `audit R07` | аксиомы теорем записи |
| `statement Имя.Теоремы` | формулировка теоремы Lean, как её видит разбор |
| `tex paper/main.tex` | собрать статью |
| `doctor` | проверить окружение |

Литература — `python scripts/sources/lit.py …`:

| Команда | Действие |
| --- | --- |
| `find "запрос"` | кандидаты в zbMATH и arXiv; `--in mathnet` — журналы MathNet |
| `cites S2` | кто цитирует источник; `--refs` — его список литературы |
| `add 2107.12209 --role "…"` | добавить работу по номеру arXiv, `mathnet:…` или DOI |
| `attach S31 файл.pdf` | прикрепить файл, полученный вручную |
| `search "запрос"` | поиск по полным текстам; запрос по-русски или по-английски, формулы в LaTeX |
| `show 1234 -n 1` | найденный кусок целиком, с соседями |
| `list` | источники реестра |

Поиск по текстам сочетает совпадение слов и смысловую близость. При первом запуске он
скачивает модель размером около 0,5 ГБ.

## Обновить инструменты в старом проекте

Когда шаблон изменился, из папки шаблона:

```
python tools/create.py --update ..\Spectra --dry-run
python tools/create.py --update ..\Spectra
```

Первая команда показывает, что изменится, вторая переписывает правила, скрипты, агентов,
команды и скиллы. Постановка, записи, идеи, источники, библиотека Lean и статья остаются
как были.

Для DeepSeek Harness отдельного обновления нет: его skills и роли собираются из тех же
агентов, команд и скиллов. `tools/create.py --update` пересобирает их сам, а после своей правки
в `.claude/` или `.mcp.json` это делает `python scripts/host/harness.py prepare` или следующий
`run`. Что получит Harness, показывает `python scripts/host/harness.py list`.

Проверку patch настоящими схемами Harness запускайте из корня набора. Ей нужен каталог
node_modules с закреплённым пакетом Harness — его печатает
`python template/scripts/host/harness.py package`; подойдёт установка в отдельный каталог
или кэш npx:

```
python template/scripts/host/harness.py prepare
node tests/template/harness_runtime.mjs <каталог node_modules> [--mcp] [--project <каталог проекта>]
```

По умолчанию скрипт проверяет заготовку `template/`; ключ `--project` называет другой
проект, а `--mcp` дополнительно поднимает MCP-серверы и сверяет их инструменты.

## Если что-то не работает

- `proj.py check` печатает ошибки и замечания. Ошибки исправляются до новой работы;
  замечания — список дел: запись без рецензии, устаревшее соответствие, источник без
  карточки, идея без критики.
- `lake build` идёт часами — не выполнен `lake exe cache get`.
- MathNet не отвечает. В Windows скрипт обходит туннель сам для хостов из
  `direct_hosts` в `project.toml`; в Linux и macOS нужно прямое правило для `mathnet.ru`.
- Имя из Mathlib, найденное внешним поиском, не существует — внешние сервисы индексируют
  другую версию. Имя проверяется в закреплённой Mathlib проекта; этим занят агент
  `mathlib-scout`.
- Инструменты ведут себя странно после правки `scripts/`: python-тесты набора
  (`python -m unittest discover -s tests/template`, `python -m unittest discover -s tests/kit`)
  запускаются из корня набора; в самом проекте python-тестов нет.
- В Harness нет команды, роли или инструмента MCP. `python scripts/host/harness.py list`
  показывает, что адаптер собрал; `python scripts/host/harness.py check` — устарели ли
  производные файлы. Запуск идёт только через `harness.py run` или с ключом `--patch`,
  после пересборки Harness перезапускается. Остальное — в `DEEPSEEK.md`.
