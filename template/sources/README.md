# Источники

Реестр — [papers.json](papers.json); по нему собран [catalog.md](catalog.md) со ссылками,
статусами и контрольными суммами. Карточки проверенных теорем — `cards/S*.md`. Полные
тексты и поисковый индекс лежат в `output/literature/`, вне Git; файлы восстанавливает
`python scripts/sources/lit.py fetch`.

## Инструмент

Всё делает `python scripts/sources/lit.py КОМАНДА` (или `uv run scripts/sources/lit.py КОМАНДА`: тогда
зависимости ставятся сами). Те же действия доступны как инструменты MCP-сервера `lit`.

| Команда | Действие |
| --- | --- |
| `find "запрос" [--in zbmath\|arxiv\|mathnet\|crossref\|openalex\|s2\|all]` | кандидаты с аннотациями; без `--in` — zbMATH и arXiv, `all` — zbMATH, arXiv, Crossref, OpenAlex |
| `doi 10.3934/math.2026892` | метаданные DOI: журнал, том, страницы, авторы, аннотация, открытый PDF, число цитирований |
| `cites S2 [--refs]` | кто цитирует источник (OpenAlex, затем MathNet и Semantic Scholar) или его список литературы |
| `add 2107.12209 mathnet:rm9740 10.1070/RM9740 --role "…"` | добавить работы: метаданные, текст, каталог, индекс |
| `add-file ПУТЬ_ИЛИ_ССЫЛКА --title … --authors … --version … --url … --name … --role …` | источник без arXiv, MathNet и DOI |
| `attach S31 ПУТЬ_ИЛИ_ССЫЛКА` | прикрепить PDF или LaTeX, полученный вручную |
| `annotate файл.json` | записать описания источников из JSON вида `{"S34": {…}}` |
| `audit` | проверить описания источников и связи с проектом |
| `pdf S22` | скачать PDF: по нему сверяются номер теоремы и страница |
| `pages S22 [--range 3-10]` | страницы PDF в PNG и их текстовый слой |
| `tex S22 [--build]` | собрать транскрипцию из частей и записать её как LaTeX источника |
| `search "запрос" [-k 8] [--code S4] [--kind theorem]` | поиск по полным текстам |
| `show 1234 [-n 1]` | кусок целиком по номеру из поиска, с соседями |
| `fetch`, `catalog`, `index`, `list` | восстановить файлы, пересобрать каталог, индекс, список |

## Откуда берётся текст

- **arXiv.** Скачивается авторский исходник: главный файл с подставленными `\input` и
  списком литературы сохраняется как `output/literature/ИДЕНТИФИКАТОР.tex`. Номеров
  теорем и страниц в исходнике нет, для карточки нужен PDF (`pdf КОД`).
- **MathNet.** По идентификатору статьи (`mathnet:rm9740`, ссылка или DOI `10.4213/…`)
  берутся метаданные со страницы статьи и PDF. Исходников на сайте нет: LaTeX делает
  команда `/transcribe`. Через VPN-туннель сайт может не отвечать, а ссылка на PDF
  работает только с cookie сессии. Скрипт держит сессию сам, а хосты из `direct_hosts` в
  `project.toml` запрашивает с адреса сетевого интерфейса вне туннеля. Этот обход работает
  в Windows; в Linux и macOS для `mathnet.ru` нужно прямое правило в VPN-клиенте.
- **DOI.** Берётся только описание из Crossref. Файл, полученный по подписке или от
  автора, прикрепляется командой `attach`.
- **Транскрипция.** `/transcribe` читает страницы PDF и пишет LaTeX по частям в
  `output/literature/parts/`; `tex КОД` собирает их, проверяет окружения, скобки и метки
  страниц и вносит файл в реестр. В тексте стоят `\pagemark{N}` с печатными номерами
  страниц и `\begin{statement}{Теорема}{6.6}` с печатными номерами утверждений, поэтому
  поиск показывает и то и другое. Транскрипцию делает модель: при расхождении первичен
  PDF, а место, прочитанное неуверенно, помечено `\unsure{…}`.

## Поиск

Поиск гибридный: BM25 по словам и близость векторов модели
`intfloat/multilingual-e5-small`, ранги складываются. Запрос пишется по-русски или
по-английски, формулы — в LaTeX. LaTeX режется на окружения теорем, определений и
доказательств и на абзацы разделов; текстовый слой PDF — по страницам. Индекс
`output/literature/index/lit.sqlite` обновляется при добавлении источника и перед каждым
поиском. Модель считает на процессоре через ONNX Runtime и при первом запуске
загружается из Hugging Face (около 0,5 ГБ).

## Поиск новых работ

К вебу прибегают, только когда работы нет ни в одной базе; `find` его заменяет.

- **zbMATH** (`find` без `--in`; поля `ti:`, `au:`, `py:`, связки `&` и `|`) — вся математика,
  включая переводные и русские журналы, с аннотациями. Основной источник.
- **arXiv** (`--in arxiv`; поля `all:`, `ti:`, `abs:`, `au:`, связки `AND` и `OR`) — препринты,
  иногда единственная открытая версия опубликованной работы.
- **Crossref** (`--in crossref`) — любые журналы по точной библиографической строке: DOI, том,
  номер, страницы, аннотация. `--in mathnet` — только журналы Math-Net.Ru (префикс `10.4213`).
- **OpenAlex** (`--in openalex`) — широкий охват, аннотации и число цитирований.
- **Semantic Scholar** (`--in s2`) — низкий лимит запросов; зовут, когда остальные молчат.
- `--in all` объединяет zbMATH, arXiv, Crossref и OpenAlex. Ошибка одной базы печатается
  строкой «ОШИБКА: …» и не обрывает остальные.

Метаданные найденного DOI сверяет `doi`: журнал, том, страницы, авторы, аннотация (до 900
знаков), открытый PDF и число цитирований — из Crossref и OpenAlex. Списки цитирования даёт
`cites`: для DOI сначала OpenAlex, затем MathNet (русские журналы), затем Semantic Scholar;
`--refs` — список литературы самого источника, откуда тоже берутся кандидаты.

## Описания источников

Название и версия не говорят, что в работе есть и чем она полезна проекту. Это записывается
в поле `about` реестра и показывается в `catalog.md` разделами «О чём», «Результаты»,
«Методы», «Связанные источники», «Ключевые слова»; если описания нет, в каталоге стоит
строка «Описание: нет».

Поля описания:

- `kind` — статья, краткое сообщение, обзор, книга, диссертация;
- `object` — что изучается: оператор, пространство, краевые условия, класс данных; от 60 знаков;
- `results` — главные утверждения с номером и страницей, если они есть в тексте;
- `methods` — чем доказано, по одному методу в строке;
- `related` — строки начинаются с кода другого источника реестра;
- `keywords` — не меньше трёх: фамилии и термины по-русски и по-английски;
- `basis` — на чём прочитано: «полный текст», «аннотация, введение и формулировки»,
  «аннотация», «название и метаданные»;
- `date` — дата составления, ставится автоматически, если не указана;
- `role` (необязательное) — заменяет связь с проектом.

`annotate` принимает JSON-файл вида `{"S34": {…}, "S35": {…}}`. При замечаниях к любому
описанию реестр не меняется: команда выходит с отказом и списком замечаний. После изменения
реестра каталог пересобирается — правило одно для всех изменяющих команд.

`audit` перечисляет: источники без описания; описание, составленное по аннотации или
метаданным, хотя полный текст уже есть; связь с проектом, дословно совпадающую с другой
записью; отложенные проверки («нужно сверить», «предстоит»). Замечание — повод перечитать
источник, а не доказательство ошибки.

## Карточки

Теорема источника становится посылкой после карточки `cards/S*.md`
(`python scripts/state/proj.py new card S4`): номер теоремы и страница по PDF, все гипотезы
вместе с соглашениями раздела и статьи, вывод, определения, применимость. Карточку по
страницам PDF сверяет агент `source-verifier` и пишет в неё раздел «Сверка»; после этого в
шапку ставится `verified`. Найденный поиском кусок — ещё не карточка.
